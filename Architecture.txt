1. What the project is

An extension of the IEEE Access 2025 paper "Trust at the Edge: ABAC-Secured Federated Learning for Smart Home Access Control Using Blockchain". The paper builds federated learning (FL) where clients hold ABAC credentials and a blockchain records trust. This project adds detection of malicious clients that hold valid credentials, using cohort-conditioned anomaly detection on their model updates plus a reputation system.

Two separate problems. Never mix their metrics:

Traffic classification (is this network flow benign/attack, which attack class): global-model quality (accuracy, F1, ROC-AUC...).
Malicious-client detection (is this FL client poisoning the model): detection AUC, TPR@1%FPR, honest clients revoked, delay... Better classification is not better detection, and neither is a blockchain benefit.

Dataset: CICIoT2023 (63 merged CSVs, 39 flow features + Label), grouped into 8 classes: Benign, DDoS, DoS, Mirai, Recon, Spoofing, Web, BruteForce. The CSVs have no device, session, capture or timestamp column. The ABAC device_type attribute is therefore synthetic: clients are assigned to device types, and the parameter rho (0..1) controls how strongly device type shapes a client's class mix.

Environments: Colab for training; the owner's Windows laptop (Docker Desktop + WSL2) for a real Hyperledger Fabric test-network (Phase 2).
